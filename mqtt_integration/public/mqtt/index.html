APP 先订阅回复 Topic，再发布服务调用。

下行 JSON · APP 发布 
{
  "id": "msg_010",
  "version": "1.0",
  "params": {
    "configs": [
      {
        "key": "volume",
        "value": "2"
      }
    ]
  }
}
上行 JSON · 设备回复 
{
    "id": "msg_010",
    "code": 200,
    "msg": "",
    "data": {
        "configs": [
            {
                "key": "volume",
                "value": "2"
            }
        ]
    }
}
APP 应在发布前订阅 invoke_reply Topic，并使用相同 id 关联请求和设备回复。code 为 200 表示设备操作成功。

登录 MQTT

支持两种登录方式：peerId + privateKey，或直接输入可用的 username + token。

输入已注册 peer 的 peerId 和对应私钥。页面会自动生成 timestamp:signature 密码。

设备端的会话 scope 必须先由可信后端写入 mqtt_authd，页面不会调用内部授权接口。

  • 如果粘贴整个 peer JSON，会自动提取其中的 id 和 private_key。
  • 浏览器端只会在本页内存中使用私钥，不写入本地存储。
  • 当前 broker 默认使用 MQTT v3.1.1 over WebSocket。
